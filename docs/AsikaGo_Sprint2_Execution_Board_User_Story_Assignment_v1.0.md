# 4. Detailed Sprint 2 User Stories

------------------------------------------------------------------------

# US-001 --- Provide Business Information

## User Story

**As an** aspiring micro-entrepreneur,\
**I want to** provide my business details, location, and registration
status,\
**So that** AsikaGo can understand my business situation and provide
relevant guidance.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-001-01

Given: The user is viewing the business assessment page.

When: The user enters business category, business type, location, and
registration status.

Then: The system stores the provided information.

------------------------------------------------------------------------

### AC-001-02

Given: Required information is incomplete.

When: The user attempts to continue.

Then: The system displays validation messages for missing information.

------------------------------------------------------------------------

### AC-001-03

Given: The user successfully submits the assessment.

When: The information is saved.

Then: The data can be used for future roadmap generation.

------------------------------------------------------------------------

# US-003 --- Create User Account

## User Story

**As a** business owner,\
**I want to** create an AsikaGo account,\
**So that** I can save my business information and continue my
registration journey.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-003-01

Given: The user selects account creation.

When: The user provides valid authentication information.

Then: The system creates an account successfully.

------------------------------------------------------------------------

### AC-003-02

Given: The user account exists.

When: The user logs in.

Then: The system provides access to saved information.

------------------------------------------------------------------------

# TE-001 --- Project Architecture Setup

## User Story

**As a** development team member,\
**I want to** establish the project architecture,\
**So that** the team can develop AsikaGo using a consistent technical
structure.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-TE001-01

Given: The project repository is created.

When: The team initializes the application structure.

Then: The React frontend and ASP.NET Core backend foundations are
available.

------------------------------------------------------------------------

# TE-002 --- Database Design

## User Story

**As a** developer,\
**I want to** create the initial database design,\
**So that** AsikaGo can store users, businesses, and registration
information.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-TE002-01

Given: The required entities are identified.

When: The database schema is designed.

Then: Tables and relationships are documented.

------------------------------------------------------------------------

# RS-001 --- Research Registration Workflow

## User Story

**As a** researcher,\
**I want to** identify the business registration workflow,\
**So that** AsikaGo can provide accurate registration guidance.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-RS001-01

Given: The registration process needs to be mapped.

When: Research is completed.

Then: The team has a documented registration flow.

------------------------------------------------------------------------

# RS-002 --- Research City Requirements

## User Story

**As a** researcher,\
**I want to** collect requirements for Quezon City, Manila, and Pasig,\
**So that** the roadmap can adapt based on location.

------------------------------------------------------------------------

## Acceptance Criteria

### AC-RS002-01

Given: A city is included in the MVP scope.

When: Research is conducted.

Then: Requirements and references are documented.
